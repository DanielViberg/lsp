## Detailed description 

In lib/Features/Abstract/Feature.vim, the FeatAu() function iterates over
servers and checks if each server is ready. When a server is not ready
(`!server.isRunning || !server.isInit`), the code uses `return` at
line 20, which exits the entire function immediately.

This means if the FIRST server in the list is not ready, NO servers get
the feature command executed. The loop never continues to check the
remaining servers. The correct behavior should be to use `continue` to
skip only the unready server and proceed to the next one.

This affects all features that use this base class method, including
DocumentSync, Diagnostics, Completion, and others. In multi-server
setups, this bug prevents any feature activation if one server is slow
to initialize.
