## Detailed description 

The Config.vim Init() function uses module-level globals `DontBotherMe`
and `CachedConfig` for initialization state. When multiple buffers are
opened rapidly (e.g., during Vim startup with multiple files), multiple
Init() calls can execute concurrently before any completes.

This race condition can cause:
- Duplicate config prompts appearing to the user
- Partial config loading where one Init() reads config before another
  has finished writing
- CachedConfig being overwritten with incomplete data

There should be a guard mechanism, such as an initialization lock or
promise-based approach, to ensure only one initialization runs at a
time. Other concurrent callers should wait for the in-progress
initialization to complete.
