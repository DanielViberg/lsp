## Detailed description 

In lib/Features/DocumentSync.vim, the AutoCmds() function contains a
blocking loop: `while !server.isRunning || !server.isInit` with `sleep 1`
inside, waiting for the server to be ready before adding autocommands.

If a server fails to initialize (crashes on startup, network failure,
missing binary), this loop will run indefinitely, causing Vim to hang.
The user cannot interact with the editor until the loop exits, and there
is no timeout or escape mechanism.

This is especially problematic during startup when multiple servers are
being initialized. A single misbehaving server can freeze the entire
editor. A timeout or iteration limit should be added, along with proper
error handling to notify the user and continue operation for other
servers.
