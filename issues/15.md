## Detailed description 

The ApplyTextEdits function in lib/Utils/TextEdit.vim has a bug in
handling overlapping or adjacent edits. The SetLines function at line 173
replaces lines directly: `lines[i0 + i] = newLines[i]` without checking
if the range has already been modified by a previous edit.

When edits overlap or are adjacent, lines at boundary positions may have
already been modified by a previous edit in the loop. The suffix/prefix
append logic at lines 176-185 can corrupt text by appending to
already-modified lines, producing garbled output.

LSP spec requires that text edits are non-overlapping and should be
applied in reverse order. If this ordering is not enforced, or if
overlapping edits are received from the server, the buffer content can
become corrupted.

Location: lib/Utils/TextEdit.vim:172-185
Severity: medium
