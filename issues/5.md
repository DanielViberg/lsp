## Detailed description 

The incremental change detection in DocumentSync.vim has off-by-one errors
in the text range calculation. The `diff()` function returns 0-based
indices, and `hunk.from_idx` represents the first changed line index.

The code calculates:
- start.line = hunk.from_idx + 1
- end.line = hunk.from_idx + hunk.from_count + 2

For a change on a single line (from_idx=0, from_count=1), this produces
start=1 and end=3, which covers 2 lines instead of 1. The end boundary
is off by one.

This sends incorrect change ranges to the language server, potentially
causing document state desynchronization. The server may receive text
documents that don't match the actual buffer content, leading to wrong
diagnostics, incorrect completions, and other feature malfunctions.
